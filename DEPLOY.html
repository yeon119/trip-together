앱으로 돌아가기

Firebase + GitHub Pages
무료 배포 안내

이 앱은 빌드와 별도 서버 설치 없이 배포할 수 있습니다. 여행 데이터는 Firestore에 저장하고, 화면은 GitHub Pages에서 제공합니다.

무료 유지: Firebase는 결제 계정을 연결하지 않은 Spark 요금제로 만드세요. Cloud Functions, Storage, 전화번호 인증은 사용하지 않습니다. 무료 한도 초과 시 서비스가 제한될 수 있습니다.

1. 먼저 내 컴퓨터에서 체험하기

  1. Node.js가 설치된 컴퓨터에서 이 폴더를 터미널로 여세요.
  2. npm start를 실행하세요. 추가 패키지 설치는 필요 없습니다.
  3. http://127.0.0.1:4173에 접속하세요. 종료는 터미널에서 Ctrl+C입니다.

설정값이 비어 있으면 체험 모드가 됩니다. 체험 데이터는 해당 브라우저에만 저장되며 친구와 동기화되지 않습니다. HTML 파일을 더블 클릭하는 대신 위 주소로 열어주세요.

2. Firebase 무료 프로젝트 만들기

  1. Firebase 콘솔에서 프로젝트를 만드세요. 이름 예: trip-together. Google Analytics는 이 앱에 필요하지 않습니다.
  2. 요금제가 Spark인지 확인하세요. 결제 계정 연결이나 Blaze 전환은 필요 없습니다.
  3. 프로젝트 개요에서 웹 앱 추가(</>)를 선택하고 앱을 등록하세요. Firebase Hosting은 설정하지 않아도 됩니다.
  4. 프로젝트 설정 → 일반 → 내 앱 → 웹 앱의 SDK 설정에서 firebaseConfig 값을 찾으세요.
  5. 이 폴더의 firebase-config.js 안에 apiKey, authDomain, projectId, appId를 복사해 넣으세요. 나머지 웹 설정 항목이 있어도 괜찮습니다.
export const firebaseConfig = {
  apiKey: "콘솔에 표시된 값",
  authDomain: "프로젝트ID.firebaseapp.com",
  projectId: "프로젝트ID",
  appId: "콘솔에 표시된 값"
};

위 웹 설정은 앱 식별용으로 브라우저에 공개됩니다. 서비스 계정 JSON, 개인 키, 계정 비밀번호는 코드에 넣거나 공유하지 마세요. 실제 데이터 권한은 아래 보안 규칙으로 제어합니다.

3. 익명 로그인 켜기

  1. Firebase 콘솔 → Authentication → 시작하기.
  2. Sign-in method(로그인 방법)에서 익명(Anonymous)을 사용 설정하고 저장하세요.

사용자는 회원가입 화면 없이 참여합니다. 브라우저에 남은 인증 정보로 본인 응답과 방장 권한을 유지합니다. 다른 기기·브라우저·시크릿 창에서는 다른 사용자로 인식됩니다. 브라우저 데이터 삭제 후에는 이전 권한을 복구하는 기능이 없습니다. 방장은 확정까지 같은 브라우저를 사용하세요.

4. Firestore 데이터베이스와 보안 규칙

  1. Build → Firestore Database → 데이터베이스 만들기.
  2. Standard 에디션, 기본 데이터베이스 (default)를 선택하세요. 지역은 이용자 가까운 곳(예: 서울)을 선택합니다. 위치는 나중에 쉽게 바꾸지 못합니다.
  3. 프로덕션 모드로 시작하세요.
  4. Rules(규칙) 탭에서 이 폴더의 firestore.rules 전체를 복사해 기존 규칙을 교체하고 Publish(게시)하세요.

규칙은 전체 여행 방 목록 조회, 다른 사람의 응답 수정, 방장이 아닌 사람의 날짜 확정을 차단합니다. 확정된 여행은 응답 수정도 잠깁니다. 긴 무작위 방 ID가 있는 초대 링크를 아는 사람은 해당 방과 응답을 볼 수 있으므로 링크는 친구들에게만 공유하세요. 공개 서비스용 초대 승인·남용 방지·자동 삭제 기능은 포함하지 않았습니다.

5. GitHub Pages에 올리기

  1. GitHub 새 저장소를 만들고 이름을 trip-together, 공개 범위를 Public으로 선택하세요. GitHub Free에서 Pages를 사용하려면 공개 저장소를 사용합니다.
  2. Add file → Upload files로 앱 파일을 업로드하고 Commit changes를 누르세요. index.html이 저장소 최상위에 있어야 합니다. ZIP 자체를 올리지 말고 압축을 푼 파일을 올리세요.
  3. 필수 배포 파일: index.html, styles.css, app.js, core.js, store.js, firebase-config.js, DEPLOY.html. 보안 규칙은 Firebase에도 따로 게시해야 합니다.
  4. 저장소 Settings → Pages → Source: Deploy from a branch → Branch: main, Folder: /(root) → Save.
  5. 배포 완료 후 Pages 화면에 표시되는 https://깃헙아이디.github.io/trip-together/ 주소를 여세요. 반영에는 몇 분 걸릴 수 있습니다.
  6. Firebase Authentication → Settings → Authorized domains에 깃헙아이디.github.io를 등록하세요(https://와 경로 제외). 이후 다른 로그인 방식을 추가할 때도 이 도메인을 사용합니다.

추가 빌드 설정이나 유료 도메인은 필요 없습니다. 새 코드를 저장소에 올리면 Pages가 다시 배포합니다. URL의 #room/... 부분까지 포함해야 같은 여행 방에 접속합니다.

6. 친구에게 보내기 전 확인

  1. 배포 주소에서 새 방을 만들고, 닉네임과 가능한 날짜를 저장하세요.
  2. 초대 링크를 복사하여 다른 휴대폰 또는 다른 브라우저에서 열고 두 번째 응답을 저장하세요.
  3. 양쪽에서 같은 응답과 추천 일정이 표시되고, 새로고침해도 유지되는지 확인하세요.
  4. 두 번째 참가자에게 방장용 ‘이 날짜로 확정’ 버튼이 없는지 확인하세요.
  5. 방장이 날짜를 확정하면 양쪽 응답 수정이 잠기고, 확정 취소 시 다시 열리는지 확인하세요.

예정 인원만큼 응답하기 전에는 ‘전원 가능’으로 표시하지 않습니다. 실제 응답자가 예정 인원을 넘으면 실제 응답자 전원이 가능해야 ‘전원 가능’입니다. 여행 전체 날짜가 가능해야 참여 가능 인원에 포함됩니다.

문제가 생기면

  • 계속 체험 모드: firebase-config.js가 올바르게 저장·배포됐는지 확인하세요.
  • 익명 로그인 오류: Authentication의 Anonymous 제공자를 활성화하세요.
  • 접근 권한 오류: 올바른 프로젝트의 기본 Firestore에 보안 규칙을 게시했는지 확인하세요.
  • 화면이 안 뜸: 브라우저 개발자 도구 Console에서 오류를 확인하세요. Firebase SDK는 Google CDN에서 불러오므로 인터넷 연결이 필요합니다.
  • 저장이 완료되지 않음: 네트워크와 Firestore 사용량을 확인하세요. ‘저장했어요’ 메시지가 나오기 전에는 저장 완료로 간주하지 마세요.

날짜 계산 자동 검사는 npm test로 실행할 수 있습니다. 실제 Firebase 연결과 보안 규칙 동작은 프로젝트 연결 후 위의 다중 브라우저 검사와 Firebase 규칙 시뮬레이터로 추가 확인하세요.
